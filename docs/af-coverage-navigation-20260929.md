# 房颤复核：覆盖检查与未评估时段导航

## 依据与范围

长期心电外部验证发现过自动 QRS 输入整段无法评估的记录，不能解释成“无房颤”。原界面仅在重分析确认框中显示跳过窗口数量，医生不易找到具体缺口。本轮把已有生产筛查器的窗口质量结果接入复核工作流，不修改筛查阈值，不部署离线熵候选，也不改原始波形或已有诊断。

## 完成的路径

1. 总览 → 房颤 / 房扑分析 → **检查全程覆盖**或**检查选区覆盖**。检查只读，不要求保存片段；不足 30 秒的选区也能检查并显示未评估。
2. 显示本次范围、逐搏修订、已评估 / 总时长和未评估时长。按秒数而非窗口个数计算比例，5 秒尾窗只占 5 秒；覆盖率不是正常率，已评估未提示也不能排除房颤。
3. 展开未评估时段，按实际原因定位：不足完整 30 秒、有效 N-N 间期不足、有效比例不足或有效时间覆盖不足。相邻同原因窗口合并，原因不同或中间可评估则不合并；每页最多 20 段。
4. **回看波形**同步 RR 选区及连续波形。波形上方提供上一 / 下一未评估时段及返回列表，支持键盘，避免反复滚动寻找缺口。记录末端保留前文：120–125 秒的缺口在 115–125 秒波形窗口中定位到 120 秒，不请求记录外数据。
5. 重分析候选仍需确认才保存；无可评估窗口时拒绝保存，但覆盖结果仍可查看。病例、逐搏修订、数据对象或读取代次变化会使旧结果失效；重载中与读取失败时不使用旧索引继续检查。
6. 网页报告和 PDF 的房颤页均注明：仅汇总已保存片段，不证明全程已评估，无片段或未提示不能排除房颤。临时覆盖检查不冒充已保存报告的覆盖证据。

## 验证

- 新增 32 项覆盖汇总、非法窗口、2,880 段分页、实际 UI 函数生命周期、陈旧依据、只读定位、重载失败及网页 / PDF 文案一致性测试。已有零覆盖重分析测试新增断言，确认拒绝保存前仍发布覆盖结果。
- 专项 92 项通过；完整回归 **1,020 passed，216.16 秒**，1 条既有重复 ZIP 测试警告。第一次专项有 1 项测试夹具使用错误网页模型字段，修正为真实的 `case` / `evidence` 契约后通过，没有放宽生产判断。
- 隔离合成病例与独立 SQLite：125 秒中 90 秒可评估（72.0%），60–90 秒有效间期不足，120–125 秒为尾窗。选区检查 60–90 秒明确为 0 / 30 秒，不显示正常结论。
- 浏览器实际完成：全程检查 → 展开原因 → 回看 60 秒 → 键盘下一缺口 → 定位 120 秒 → 返回原列表 → 选区检查。结束后节律修订仍为 1，原 pending / confirmed / excluded 共 3 条，确认负荷 8% 不变。没有操作真实病例诊断。
- 桌面 1366×900、窄屏 390×844；窄屏正文 14 px、控件 16 px / 44 px，页面宽度 390，无横向溢出；控制台无 error / warn。初轮后补齐波形侧的连续缺口导航与返回路径，最终一轮确认通过，视口已恢复、测试标签页已关闭。
- 静态演示在新临时目录构建，仅同步本轮相关资源；没有远端发布。JS 语法与 diff 空白检查通过。
- 设计检查一次：0 主问题、34 项建议；大多数属于原有概览样式，新增 16 px 移动控件字号是可操作性所需，不为消除建议而缩小。局部完成评审为 `ship`，不代表全站无障碍、临床有效性或目标设备验收通过。
- 8765 原服务因报告模块更新返回分析依据 409，按原命令受控重启后健康正常、10 例可读 / 0 例不可读、分析依据及新 JS 资源均 200。未刷新用户现有标签页。

## 尚未完成

覆盖结果仅针对当前病例已加载的逐搏索引和固定工程筛查规则；不保证记录中所有真实房颤可识别，也不是波形信号质量的全面验证。尚无临床医生在目标 Windows / 打印机上的完整任务效率验收。真实设备标定、短事件漏提示、其他节律误提示及独立临床性能仍待解决。

下一步以医生完整核查任务审视报告候选、波形和选图之间的往返成本，结合实际等待时间与操作数优化布局；算法改进另按固定方案评估，不能用界面完成或汇总指标掩盖失败记录。
