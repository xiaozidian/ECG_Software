# 医生工作流与交互优化依据

核对日期：2026-09-05。对象：本地开发版及单病例静态 Demo。此文为软件设计记录，不是临床有效性证明。

## 官方产品资料得到的启发

| 产品与一手来源 | 可核对的功能方向 | 对本项目的取舍 |
|---|---|---|
| [GE CardioDay](https://www.gehealthcare.com/en-in/products/diagnostic-ecg/cardioday-holter-ecg-software) | 引导式分析、医生控制分析过程、报告保存及 MUSE 集成 | 同一病例贯穿复核到报告；访问页面与医生确认分开。未实现 MUSE 接入 |
| [SCHILLER medilog DARWIN2](https://schillerus.com/medilog-darwin2-holter-analysis-software/) | 形态编辑、噪声复核、图条选择、可编辑报告 | 分清形态分型与逐搏改型，保留证据能回看原始波形；不照搬其自动识别性能宣称 |
| [Philips Cardiologs](https://www.usa.philips.com/healthcare/service/cardiology-solution-clinicians) | 关键事件复核、降低编辑负担、图示化报告与协作 | 以当前待处理任务组织界面；不把算法候选直接当诊断 |

这些是官方公开功能说明，不是对其他产品实际临床工作站的测试。下述流程是结合本项目能力作出的设计推断，不宣称功能或医学性能等同。

## 一条主路径

工作台选患者 → 波形质控与定位 → 模板/心搏改型 → 趋势与 HRV 核对 → ST-T 人工复核 → 事件取舍 → 结论草稿 → 审核 → 返回工作台。

每页只有明确的主职责。医生可跳转和回看，不能把“点过页面”变成“已复核”。顶部保留病例与当前任务；主操作是显式确认，次操作只是浏览。报告审核前检查列出未确认环节与可回看的证据。

## 本轮实现

- SQLite 持久化五个环节状态、确认备注、操作者与时间，版本校验防止确认过期数据；Demo 镜像同一行为但仅写浏览器。
- 人工改型、模板、标注、患者资料与事件处理按依赖关系使确认失效，并让已审核报告退回草稿。与源数据分离，不覆盖 DATA/EBI。
- 事件队列支持每页 100 项、保留/排除/待核；回看后返回原页。报告优先读取最多 20 个保留事件的代表图条，完整保留列表仍在审核前检查与本地 PDF 定位索引中可查。
- 保存草稿、审核、导出分别呈现；未确认或空结论不能审核；未保存离页提醒。
- 保留 N/S/V/X 类别入口，连续波形增加可见的逐搏改型按钮，与键盘/右键共享同一覆盖层；散点圈选片段的右键以该片段锚定心搏为目标。
- 减少重装饰，强化控件文字、焦点、状态含义。桌面密集区域内部滚动，窄于 860 px 提供横向访问回退，不通过继续缩小文字隐藏控件。
- 发布包对 JS/CSS 添加内容指纹，避免旧 Demo 适配器与新版页面混用。
- 修复通用画布强制最小 300 px 的错误；小型心搏卡按真实容器绘制完整时间窗，避免裁掉波形。紧凑模板库优先保留连续波形，代表片段改为横向内部滚动。

## 仍不能混淆的边界

1. 确认是医生主动记录，不是系统认证其医学结论正确。事件环节允许抽查后确认，未处理源候选仍为待复核。
2. 后续右键编辑迭代已加入修订版本、位置编辑、RR/HRV/事件重算及差异预览；参见 [算法与编辑规范](beat-editor-research.md)。源报告正文不自动改写，下一阶段仍需独立临床数据验证。
3. ST-T 幅值标定和自动定位尚未验证，继续仅提供人工复核，不开启诊断性 mV 或缺血诊断。
4. 服务端 PDF 是研究复核摘要和证据定位索引，不是全部勾选波形页的完整报告包。Demo 不生成服务端 PDF。
5. 本地操作者字段不是身份认证或合规电子签名；多人并发事务、RBAC、签名及审计防篡改仍需专项工程。

## impeccable 的使用

先核对官方版本，再将个人 Codex 技能从 3.8.0 升级到 [4.2.0](https://github.com/pbakaus/impeccable/releases/tag/skill-v4.2.0)，保留原版备份。采用其 Operate 的可扫描、任务优先、清晰反馈原则，不把视觉偏好当作医疗软件交互或诊断的权威。

## 验证范围

回归覆盖确认版本冲突、审核前置条件、上游修改失效、事件持久化与输入校验、存储重载、Demo 对等行为、发布资源指纹及既有病例数据边界。另以本机静态 Demo 检查导航、编辑、事件回看和报告流程；具体运行结果见本次工作回执。
