# 后端波形心搏索引复用验证

日期：2026-09-29。优化连续波形及小波形的标签读取，不修改采样值、心搏分类、RR 定义或报告计算算法。

## 瓶颈与实现

此前每次小波形请求都会将全记录源心搏与人工修订重新合并，构建 `EditedRecords`。只显示附近几十搏，也会重复构建约十万搏。此次在 `app.py`、`ecg_core/clinical_query_cache.py` 新增应用实例私有的 `WaveformBeatCache`，仅服务 `/waveform`、`/event-waveform`、`/event-waveforms` 的标签窗口投影。

- key 绑定病例、原始 DATA/EBI/LPS 与执行程序的内容依据、工作流修订版本。数据或编辑变化不能命中旧 key。
- 复用既有只读查询缓存的同 key 并发共享构建、LRU、等待超时和失败恢复。等待超时返回可重试的 503，不返回旧标签或重复启动同一构建。
- 最多两个索引、合计 600,000 个结构计数单位。计入 beats、markers、records、record_samples、by_sample、修订项和排除节律区间的长度；不是精确内存字节／RSS 上限。超限结果可完成请求，但不长期保留。
- 只复制实际窗口内的标签给调用方。统计、报告和编辑计算仍独立创建修订视图，不取得或改写缓存对象。
- 新构建完成、窗口投影后、接口返回前仍核对依据；热缓存不能绕过来源缺失／损坏检查。DATA 每次重新读取，不缓存 ECG 样本。
- 连续波形保留非 QRS 标记，事件小波形保留原有标签口径；原始／修订模式分离。移动／删除后 RR 从完整修订记录重建，不采用局部切片猜测前一心搏。

本轮没有修改前端或静态 Demo 资源。

## 可复现基准

```sh
.venv/bin/python scripts/benchmark_waveform_labels.py \
  --output /tmp/new-waveform-benchmark.json --beats 100000
```

脚本拒绝覆盖已有证据。生成合成 EBI、稀疏全零 DATA 和独立数据库，退出时清理临时输入，不读取患者数据。各配置发送八个不同窗口请求，每批 24 个 2.4 秒片段、II/V1/V5、最多 1200 点。对照只禁用缓存复用，来源／修订校验保持不变。计时包括 Flask 测试客户端处理与 JSON 解析，不含浏览器、网络和绘图。

| 场景 | 全记录构建次数 | 请求中位耗时 | 排除首请求后的中位耗时 |
| --- | ---: | ---: | ---: |
| 顺序、关闭复用 | 8 | 192.84 ms | 191.28 ms |
| 顺序、开启复用 | 1 | 15.26 ms | 14.88 ms |
| 两路并行、关闭复用 | 8 | 393.84 ms | 不适用 |
| 两路并行、开启复用 | 1 | 40.78 ms | 不适用 |

开启／关闭复用的所有对应响应 SHA-256 完全一致，包括样本、标签、RR 与依据字段。保留一个索引、400,000 结构单位，结束时 pending=0。配置顺序运行受操作系统文件缓存影响，首请求不称为独立冷启动；后续请求结果也不是整页提速倍数或目标电脑上的固定承诺。

完整测量、环境和源文件摘要：[benchmark-100k.json](validation/waveform-labels-20260929/benchmark-100k.json)。
