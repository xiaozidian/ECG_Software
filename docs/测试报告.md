本轮结果仅证明软件在现有十病例上的功能链路和回归状态，不构成心律分类、事件检出或测量结果的临床准确率验证。

## 7. 测试中发现并修复的问题

### 7.1 非 ASCII HTTP 响应头兼容问题

- 现象：包含非 ASCII 字符的 HTTP 响应头在部分运行环境下存在编码兼容风险。
- 处理：调整响应头内容与编码策略，避免在 HTTP 头中直接传递不兼容字符。
- 复测：相关接口及打包烟雾测试通过。

### 7.2 原始报告隐私泄露风险

- 现象：原始报告访问链路存在未经授权暴露敏感内容的风险。
- 处理：收紧原始报告访问控制，并在界面使用隐私占位符。
- 复测：未授权访问返回 HTTP 403；浏览器页面未显示原始身份信息。

### 7.3 默认 PDF 与会话授权

- 现象：遮蔽界面下导出的 PDF 仍可能带完整身份字段，且仅使用查询参数不足以构成授权。
- 处理：增加当前浏览器会话授权；默认 PDF 将姓名和患者 ID 改为“已遮蔽”，显式授权并请求明文时才输出身份字段；恢复遮蔽会撤销会话授权。
- 复测：无会话授权时，即使直接添加 `include_phi=1` 仍为遮蔽；授权前后 PDF 均实际生成，并核对 `X-Privacy-Mode`。

### 7.4 患者资料输入与报告同步

- 现象：非文本姓名等异常 JSON 可进入覆盖层并导致后续页面报错；患者资料覆写未同步至 PDF。
- 处理：增加字段类型、年龄范围、性别枚举和布尔值校验，PATCH 改为合并语义；PDF 先合并本地患者覆写，再按隐私授权脱敏。
- 复测：异常输入返回 400 且工作台继续可用；有效覆写在病例 API 和 PDF 中保持一致。

### 7.5 PDF 视觉检查

- 将最终默认脱敏报告渲染为 150 dpi PNG，检查中文字体、标题层级、表格、结论换行、免责声明、页脚和页码。
- 另以接近字段上限的约 500 字诊断进行压力渲染，报告自动扩展为 2 页，患者信息单元格按中文自动换行。
- 结果：正常报告和长字段压力报告均未发现文字截断、重叠、乱码、黑块或超出页面边界。

### 7.6 散点复核发布前审查

- 小时散点最初实现为“时间–RR”图，与对标界面的小时 Lorenz 语义不一致；现改为主波形焦点所在整点一小时内的 RR(i)–RR(i+1)，GET 与精确圈选共用同一小时窗口。
- 快速切换病例可能让旧病例响应覆盖新病例页头；现以病例请求代次和病例号双重校验，波形、趋势、事件和散点各自隔离过期响应。
- 快速拖动超长片段列表可能堆积屏外请求；现限制最多两批并发、只保留最新可视队列，并在圈选、病例或滤波变化时中止旧片段请求。
- 发布审查发现测试曾写入可关联的真实病例目录标识与逐例精确计数；该测试已删除并由纯合成 EBI 语义测试替代，真实病例、截图、数据库、配置和构建产物均未进入待提交集合。

## 8. 适用边界与后续验证要求

本次十病例测试仅用于功能回归，包括数据读取、界面交互、事件筛选、趋势与 HRV 展示、报告编辑与导出、打包运行以及隐私控制。它不能替代临床验证，也不能据此声明算法的灵敏度、特异度、阳性预测值、阴性预测值或诊断一致性。

如需进入临床研究、医疗器械注册或临床使用评估阶段，应进一步使用具有专家逐搏和逐事件标注的更大规模、多中心、覆盖多种节律与噪声条件的数据集，并由具备资质的临床专业人员完成独立复核和统计学评价。
