# 房颤／房扑确认状态与负荷一致性

## 面向医生的改变

房颤页的列表上方分别展示已确认房颤、已确认房扑的片段数、秒数和记录时间占比，并列出待复核数量。只读已保存片段，表单中尚未保存的选择不会提前改动统计。窄屏数值与说明使用 14px、可换行布局；保留现有工作台配色和导航。

报告的房颤／房扑附页采用同一口径，说明分母、合并去重、待复核不入确认负荷和未评估范围的限制。小时统计后端与离线演示也返回相同结构；现有小时表的房颤／扑列仍是片段起始次数，不把它改称持续时长。

## 计算契约

- `rhythm_summary` / `rhythmSummary` 输入已保存的半开片段 `[start_s, end_s)`，拒绝非有限数、布尔时间、非正时长及未知节律／状态。
- 房颤与房扑分别计算确认区间的时间并集；合并负荷再对二者取并集，不能直接相加。按统计范围裁切，不让记录外区间增加负荷。
- 分母是完整记录时长（小时统计使用该小时与记录交集的实际长度），不是算法已评估时长。无时长时为缺失，不伪造为 0%。0 确认负荷也不代表排除房颤。
- 片段次数归入开始时间所在的半开小时。跨小时片段在后续小时可以有覆盖秒数而新增次数为 0；另保留相交片段数，避免混淆。
- 待复核和已排除片段不进入确认负荷；同一区间同时存在确认和待复核记录时，两条医生记录均保留，确认秒数仍只算一次。

## 两层确认不得互相替代

`rhythm_status` 表示片段确认；`diagnosis_status` 仍保留报告整体编辑审核门槛。医生确认片段后，即使整体尚未审核，页面可以显示确认负荷，但不能绕过整份报告的审核。

收尾发现并复现一条状态泄漏：源 A／M／C／H 心搏标记生成的连续片段，在完成编辑审核后会被报告列表标成确认，虽然节律状态还是 pending。现在四类源片段的两个状态均保持 pending，直到医生通过片段工作流明确保存确认。审核待复核图条时明确提示“在房颤／房扑页完成片段诊断确认，或从报告中移除该图条”，不让医生重复已经完成的整页审核。

源标记片段的末端延伸到下一类型心搏或记录末尾，与房颤编辑器初始片段一致。已保存片段沿用包含末采样的存储表示，在事件转换时加一个采样变为半开终点。200 Hz 仍是导入约定，不表示设备已核验。

AF 选图依据升级为 `episode-status-v2-inclusive-end-v1`，索引版本为 `af-end-v1-status-v2`；旧状态口径的选图不能直接获准，其他类别专属依据不因该后缀改变。程序构建变化也受现有重启／审核失效保护约束。没有改自动 RR 筛查阈值、窗长或候选聚合，没有把旧外部验证结果套用到新构建。
