# 心搏改型后的连续复核位置

## 解决的问题

原 `loadOccurrences()` 每次清空列表后都把 `scrollTop` 设为 0。医生在中段记录改型、删除、恢复或撤销后，需要重新找到原来的时间。旧序号也不可靠：一次批量改型可能移走许多前置记录。

现在保存的是当前筛选内的采样位置，而不是旧序号。小图右键或键盘改型使用该事件的起始采样点；从连续波形或撤销栏进入时保留列表当前可见行的时间。刷新后在同一筛选内寻找该位置或后方第一条记录；若已到末尾则显示最后一条，集合为空时显示 0 条。明确称为“原时间位置”或“原位置附近”，不冒充原事件身份。

## 交互及安全边界

- 列表回到对应行，跳转序号同步更新；“继续复核第…条”按钮将键盘焦点交还小图，但不勾选心搏、不写诊断，也不改变连续波形时间。
- 改型后依然清空旧批量选择，防止下一次操作误用旧集合。
- 病例、加载批次、筛选或页面已经变化时，旧书签失效；新筛选请求及其界面不被旧刷新覆盖。
- 等待重算时若医生主动滚动列表，改为保存新可见位置，不拉回旧位置；同时仍更新记录依据。
- 保留模板搜索草稿。普通筛选切换仍从第一条开始，原有手动序号跳转语义不变。
- 浏览器实际会把短加载提示下的滚动位置压到 0，因此先建立虚拟列表总高度，再设置滚动位置。该问题在 DOM 模型通过后由真实浏览器发现并修正，模型已补充这一约束。
- 接口 `near_sample` 仅用于心搏记录浏览，校验非负安全整数；不影响报告 `locate_event` 的严格身份定位，也不修改数据、计算口径或诊断。

## 实现

- `ecg_core/clinical_analysis.py`、`static/js/clinical-analysis.js`：在已筛选且按时间排序的集合中二分寻找采样点，仅构造当前页；Python 与离线演示口径一致。
- `static/js/clinical-ui.js`：书签、失效保护、虚拟高度恢复、继续复核入口。
- `static/js/beat-editor-ui.js`、`static/js/app.js`：在修订成功后的工作区重载中传递书签，不改变原有病例/选择竞态保护。
- 静态演示脚本及缓存摘要同步。
