# 心搏修订快照读取优化

## 问题和改动

只读读取当前心搏修订时，原实现会从 SQLite 取出并在 Python 中解析 `document`、完整 `undo` 和 `redo`。波形标签、概览、ST-T、报告和改型菜单等路径因此承担与历史体积相关的额外分配。`edited_feed(case, document)` 即使已收到当前文档，也会再读取一次完整历史；普通预览前后两次统计分别重复这一步。

新增 `BeatEditorStore.snapshot()`，以一个 SQL 语句读取当前文档、版本和撤销／重做是否可用。SQLite 使用 `json_array_length` 读取历史数量，不把历史文档传回 Python。旧 SQLite 缺少该函数时精确回退到原读取路径；不吞掉数据库锁定、损坏 JSON 等异常。

应用只读路径使用快照；已经拿到文档的 `edited_feed` 不再读库。QRS 搜索使用同一快照的设置和心搏文档。报告修订数及版本来自同一快照。

提交、撤销、重做仍在原 `BEGIN IMMEDIATE` 事务中读取完整历史，保持原版本冲突、历史上限、审核失效与审计语义。本次不是缓存，不新增数据表，不修改原始 DATA／EBI，不改变心搏计数、RR、HRV 或诊断公式；网页及静态演示接口结构不变。

## 可复现基准

命令：`.venv/bin/python scripts/benchmark_editor_snapshot.py --repeats 7`。

纯合成临时数据库，每份当前或历史文档含 10,000 条改型记录；各路径预热后读取 7 次，计中位数；另行用 tracemalloc 测 Python 分配峰值。每组结果先验证当前文档、修订版本和历史可用状态与旧路径一致。

| 撤销历史份数 | 历史字节 | 原读取中位 ms | 快照中位 ms | 原 Python 峰值 MiB | 快照峰值 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 2 | 4.003 | 3.933 | 3.617 | 3.617 |
| 1 | 759,085 | 7.987 | 5.376 | 7.034 | 3.617 |
| 6 | 4,554,510 | 28.646 | 11.693 | 21.755 | 3.617 |

这只衡量存储快照路径，不是整页加载时间、冷启动性能或整个进程的内存峰值；SQLite 仍解析历史数组，tracemalloc 不统计 SQLite 原生内存。没有历史时收益很小，历史越大避免的 Python 对象分配越多。测试不以墙钟阈值作为通过条件。

## 验证

- 新增 19 项：缺失记录、空／非空／缩进历史、返回对象隔离、仅解析当前文档、同一读事务一致性、撤销／重做和旧版本拒绝、旧 SQLite 回退及其他错误传播。
- 合成 API 比较改动前投影与快照路径：心搏编辑摘要、心搏全集、概览、RR 图、HRV、散点及房颤复核响应完全一致，并禁止只读路径调用完整历史读取。
- 改型预览与 QRS 预览只读取一份当前快照；预览前后工作文档和源 DATA／EBI／LPS 摘要不变。
- 编辑／报告失效／分析读取／波形缓存专项最终 **158 项通过（18.10 秒）**。
- 最终完整回归 **1,191 项通过（202.62 秒）**，1 条既有重复 ZIP 测试警告；新增 19 项均纳入全量，没有删除或跳过原测试。
- 首次同一专项 **157 通过、1 失败**。结构日志为 `ecg_core.beat_editor` 的 `ctime_ns` 从 `1790704988375459401` 变为 `1790704989412941205`，触发既有程序更新拒绝。未记录其他元数据变化，但导致 ctime 改变的外部来源尚未确认；不以重跑通过认定该问题已修复，未放宽运行时保护。
- Python 源码编译检查及差异空白检查通过。最初 `py_compile` 因仓库字节码写权限失败，改用内存 `compile` 检查，不为此扩大写权限。
- 8765 按原配置受控重启；健康接口 `status=ok`、10 例可读、0 例不可读，首页 HTTP 200。没有打开真实病例做修订／审核／保存，没有刷新用户标签页、提交或推送。
