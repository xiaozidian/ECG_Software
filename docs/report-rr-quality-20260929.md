# 报告心率与长 RR 的有效间期一致性

## 问题与范围

正常导入的逐搏物化层已经在伪差 X 处断开 RR，但下游报告与 RR 心率候选主要依赖正数 RR / HR。直接构造、遗留或不一致的索引可能绕过前一层保护。此次把报告统计、RR / NN 极值候选、快慢心率连续事件及长 RR 候选接到共享的区间校验，不声称正常导入此前普遍存在跨伪差错误。

## 当前规则

- RR 属于结束它的心搏；O / Y / T 非 QRS 标记不作为 R 峰，X 保留为断点，X 两侧间期均不计为有效。
- 使用输入顺序，不排序、补造或跨越坏区间。两个 R 峰位置须有限、非负且递增；RR 须为正有限数，与采样位置差按当前 200 Hz 导入假设换算后的偏差不得超过既有 10 ms 容差。
- 结束 R 峰必须在记录的 `[0, duration)` 内；恰好落在末尾的记录外点不计。小时归属采用间期结束时刻，整条记录与小时汇总使用同一规则。
- RR 筛选不是 NN 筛选：S / V / 房颤心搏不因非窦性而自动删除；不设置一个任意上限来排除真正长 RR。NN 极值继续另行要求连续正常搏、NN 范围和房颤／房扑排除区间。
- 心率缓存须为正有限值，且与 `60000 / RR` 相差不超过 0.051 bpm，符合当前逐搏物化的一位小数约定；不一致时拒绝用其进行心率统计，不自动修补。这是缓存一致性规则，不是临床心率阈值。
- 长 RR 与最长 RR 不依赖缓存 HR 是否存在。缺失或不一致 HR 显示为空，不丢弃有效长 RR；有效 RR 数量与可用于心率统计的间期数量分开记录。
- 报告长 RR 维持严格 `>2500 ms` 与 `>3000 ms` 两种口径；候选不自动等同停搏诊断。
- 升级极值、快慢心率和长 RR 的依据版本。旧选图草稿不作为有效证据返回，审核时明确拒绝，要求重新选择；不改写患者已有图条或结论。

时间和单位仍受设备导入假设限制。连续正常搏与一般 RR 的区分参考 [WFDB ann2rr 的 -c / -P / -p 说明](https://physionet.org/physiotools/wag/ann2rr-1.htm)；该参考不是对本项目 10 ms 容差、200 Hz 假设或临床性能的验证。

## 验证

- 新增 `tests/test_report_rr_quality.py`：23 项，涵盖伪差两侧、异常数值、RR 与采样位置不一致、HR 缓存冲突、缺失 HR 的长 RR、非窦性 RR、记录末尾、重复／逆序点、旧证据版本和真实物化层。合成数据核对 Python 与 JavaScript 的索引及报告结果，验证不修改输入。另验证实际前端顺序中 report-engine 先于 rr-quality 加载仍可调用。
- 新专项加静态演示测试：28 passed，2.62 秒。JavaScript 语法、diff 空白检查通过。三个演示脚本与资源索引已同步。
- 最终完整回归：855 passed，168.59 秒；仅 1 条既有损坏备份用例中的重复 ZIP 成员警告。相比上一轮 832 项新增 23 项。本轮未修改真实患者诊断、报告草稿或原始信号。
- 正式 8765 服务停止旧进程后重新启动：健康状态 ok，10 例可读、0 例不可读，工作台 HTTP 200。未自动刷新用户原标签页。
- 既有长 RR 测试改为要求伪差前后均断开；NN 极值测试将最后一个 R 峰放入半开记录域内，保留其原先“房颤仅抑制 NN，不抑制 RR”的断言意图。
- 全部 48 条 MIT-BIH `.atr/.hea` 使用已有校验后的公开输入重新运行：0 个计数检查差异、0 条历史整记录计数差异；Python / 浏览器事件索引一致。此处是参考标注驱动的计数验证，不是 R 峰检测、房颤诊断或自动心搏分类准确率。结果和算法快照位于 `docs/validation/mitdb-counts-20260929/rr-quality-v3/`。
