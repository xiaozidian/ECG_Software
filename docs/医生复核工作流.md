# 医生复核工作流

## 1. 软件目的

CardioInsight Holter 的核心任务，是让医生在一个连续、可回退、可追溯的病例上下文中完成动态心电人工复核，并形成报告草稿。软件首先服务于“原始波形可信、候选结果可回看、医生修改可追溯、报告内容可核对”的闭环，不把自动候选包装成独立诊断。

## 2. 主流程

| 步骤 | 医生问题 | 主要操作 | 进入下一步前应知道什么 |
|---|---|---|---|
| 1. 波形复核 | 数据能否判读，候选心搏在哪里？ | 选择 1–3 导联、缩放和平移波形、查看坐标、散点圈选、定位异常与伪差 | 原始波形和主要候选位置已经看过 |
| 2. 模板编辑 | N/S/V/X 源分组中是否混入不同形态？ | 切换源类别、形态叠加框选、自建模板、逐搏人工改型 | 哪些是源分组，哪些是医生覆盖，哪些仍待确认 |
| 3. 趋势与 HRV | 全天统计是否受异常 RR 或伪差影响？ | 核对心率趋势、RR 直方图、Poincaré 与 HRV 对照 | 统计口径、数据时长和不可比项已经明确 |
| 4. ST‑T 复核 | 自动候选是否为真实、持续的动态复极变化？ | 查看 12 导联趋势和候选原始波形、调整 ISO/J/ST60/ST80、排除体位/伪差并记录医生意见 | 软件只生成待复核候选，不生成自动缺血诊断；医生确认后才可进入报告 |
| 5. 事件候选 | 哪些候选事件需要接受、排除或进一步回看？ | 按类型筛选、核对阈值、跳回原始波形 | 报告中采用哪些候选、排除哪些伪差 |
| 6. 报告 | 如何把证据、统计和结论组织成可审核文档？ | 选择报告页、核对图条和全导联、编辑结论、保存草稿、审核或导出 | 报告状态与医生审核状态明确分开 |

## 3. 导航规则

- 工作台和患者管理属于病例外入口；选择病例后才出现六步病例工作流。
- 六个步骤始终保持同一病例，不要求医生每页重新选择患者。
- 顶部流程条显示当前步骤、已确认/待确认/修改后待复核和明确的下一步；任一步都可返回补充复核。
- 浏览不改变确认状态。“确认本步并继续”需要显式勾选，可记录备注；本地写入 SQLite 与审计，Demo 写入浏览器。只读服务不开放确认。
- 左侧导航和顶部流程条使用相同顺序与命名，避免“编辑”和“波形复核”前后颠倒。

## 4. 模板编辑中的 N/S/V/X 规则

- N、S、V、X 作为源 EBI 类别，必须在页面顶部始终可见，并同时显示英文代码、中文名称和心搏数。
- 未选中心搏时，按 `N` / `S` / `V` / `X` 或 `1`–`4` 切换源类别。
- 选中心搏后，按 `N` / `S` / `V` / `X` / `P` / `O` 写入医生人工类型覆盖；`Backspace` 恢复源类型，`Escape` 清除当前选择。
- 自建模板保留父类别和实际样本索引；它不是自动分类器，也不自动改变下游事件和报告统计。

## 5. 后续优化方向

1. 把事件“接受 / 排除 / 改类”与模板人工覆盖纳入统一的分析版本，并提供撤销、差异和可重放重算。
2. 在本轮显式确认与审核门禁基础上，进一步定义可机器验证的完成条件。当前医生可以完成抽查后确认事件环节，不强制逐一处理每个源候选；确认记录不证明所有候选都已判读。
3. 把趋势、ST‑T、事件和报告中的任意数据点统一链接回同一个原始波形定位器，减少重复页面和重复图表。
4. 增加病例级待办摘要，只显示“下一件需要医生处理的事”，而不是让医生逐页寻找未完成项目。
5. 在多人版本中把复核人、审核人、版本、签名和退回原因纳入权限与审计流程。

## 6. 已落地的闭环与边界（更新至 2026-09-28）

- 事件处理持久保存，支持分页、波形定位和返回来源；报告能查看保留证据。
- 当前强制确认环节为模板编辑和 ST-T；报告另按有结果的事件类别检查筛选完成标记。空结论、未保存修改、未完成确认或失效证据不能审核。浏览总览／HRV 不等于确认复核。
- 改型和模板修改使模板编辑、ST-T 重新待核；逐搏改型也重置事件决定。普通标注使 ST-T 待核，房颤分段修订使两环节待核。相关病例修改会撤销已审核报告状态，并更新草稿／退回报告的版本；旧窗口不能据旧版本覆盖。
- 人工修订不改源数据；当前界面的 RR、HRV 和逐搏事件使用修订序列重算，源报告摘要仍保留原值。参考 [完整右键编辑与算法边界](beat-editor-research.md)；临床验证未完成。
- 当前已有按选择导联、人工区间输出的 A4 图条 PDF；没有可验证电子签名或临床多人权限系统。设计依据见 [竞品调研](clinical-workflow-design.md)。

## 7. 保存冲突与恢复（2026-09-28）

- 版本号与本窗口已载入的结论、选图绑定；工作流刷新不能只更新版本号而保留旧正文。
- 另一窗口或病例修改导致版本变化时，当前未保存文字仍保留，停止保存／审核；“载入最新版本”需要明确确认丢弃本窗口修改。
- 保存过程中继续输入的内容不会误标成已保存；按钮在保存期间禁用，防止重复提交。
- 写入、使复核失效及审计记录使用同一数据库事务；其中一步失败会整体回滚。
- PDF 在计算开始与结束时核对报告版本、病例复核版本及计算依据（2026-09-29 升级为算法与原文件内容指纹）。发生变化则拒绝下载，不记成功导出审计；成功响应携带版本号及内容摘要。
- 这些保护不等于多人电子签名或不可篡改审计；完整交付验收见 [医生可用性验收矩阵](clinician-readiness.md)。

## 8. 读取、草稿与审核入口（2026-09-29）

- 病例读取期间显示进度状态，可切换目标步骤或返回工作台；读取完成进入最后选定的步骤。取消、失败和切换病例后的迟到结果不能把页面带回旧病例。
- 同病例资料重读保留未保存报告及其原版本。若观察到新版本，提示核对冲突，不把旧正文绑定到新版本。
- “审核前检查”在报告工作区可展开，“查看审核前检查”先展开再定位；正文／选图修改会更新待保存状态。空结论、只读、待复核、未保存、依据过期或正在保存时均不允许审核。
- “载入最新版本”先确认丢弃当前草稿；等待期间若又输入或改选图，则保留新增内容并要求重新核对，不覆盖新修改。保存期间不允许切换病例。
- 上述保护已进行实际函数的异步自动测试；修复后完整浏览器任务路径仍需按验收矩阵完成，不以功能实现代替临床验收。

## 9. 算法或原始文件更新后重新复核（2026-09-29）

- 新保存的报告绑定后端计算构建、DATA／EBI／LPS 内容及报告配置。更新算法或替换输入后，打开病例会撤销历史审核，保留医生结论和选图，要求重新确认。
- 旧数据库没有这份计算依据的历史报告也会回到草稿，不把“旧版本已审核”自动当作“新算法已审核”。保留的图条、标注和编辑不代表其依据仍有效，医生需逐项核对。
- 服务运行中检测到代码更新会拒绝继续混用新旧代码，应完成更新后重启。只读服务不能代替可写工作站重审历史报告。
- 导出期间原始文件或病例状态变化时不提供混合版本 PDF；主报告和独立 HRV 报告均带下载内容摘要。详情、缓存策略和未覆盖风险见 [报告计算依据说明](analysis-provenance.md)。
- 若提示“原始文件尚未完整下载到本地”，先在访达中下载并保留整个病例文件夹，再重试。云端占位状态不是算法正常或无事件；软件不会靠空波形填出正常报告。
