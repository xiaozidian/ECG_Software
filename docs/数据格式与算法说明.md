# 数据格式与算法说明

## 1. 文档范围与安全边界

本文记录当前 10 例 Holter 数据的已验证解析方法、可复现统计算法和已知限制。文中不包含姓名、院内号、医生等个人信息。

当前实现用于科研、教学、软件验证和人工复核辅助，不得作为未经医生审核的独立诊断工具。原始文件应始终只读；人工修订应写入独立数据库或 sidecar 文件，并保留操作者、时间、旧值和新值。

## 2. 病例目录和文件角色

一个完整病例通常包含：

- `data/*.DATA`：连续原始 ECG，是波形显示的主数据源。
- `data/*.EXAM`：私有检查信息结构，当前不解析。
- `data/*.PAC`：可选的 32 字节头加 16 字节记录，疑似起搏/脉冲候选索引；不能作为必需文件。
- `DGS/*.EBI`：逐搏采样索引、分类和 RR 间期，是 MVP 事件导航和统计的主索引。
- `DGS/*.EBT`：32 字节头加 192 字节记录的模板缓存；MVP 不依赖它。
- `DGS/*.XML`：UTF-16 分析、滤波、显示和报告参数。
- `DGS/*.DGS`、`DGS/*.EVT`：私有二进制分析状态和事件结构，当前不依赖。
- `report_image/*_1.LPS`：UTF-16 XML 报告页面，含统计、结论和版面对象。
- `report_image/*.LCA`：页面引用及签名清单。
- `report_image/*.png`、`report/*.pdf`：已生成的报告页面和 PDF。

导入时应记录每个文件的相对路径、大小、修改时间和 SHA-256。不要依据修改时间判断文件内容一定属于同一次分析。

## 3. `.DATA` 连续波形格式

### 3.1 已验证布局

10 个 `.DATA` 文件均满足以下结构：

```text
文件头：无
字节序：little-endian
采样率：200 Hz
每帧：8 × int16 = 16 字节
物理通道：I、II、V1、V2、V3、V4、V5、V6
```

计算关系：

```text
frame_count = file_size / 16
duration_seconds = frame_count / 200
byte_offset(sample_index) = sample_index * 16
```

证据包括：文件长度全部可被 16 整除；按 200 Hz 计算的时长与原报告时长仅相差秒级；抽取的 8 个交织通道均呈同步 ECG；EBI 相邻样本索引差乘以 5 ms 与其 RR 字段中位误差为 1 ms。

### 3.2 12 导联推导

胸前导联直接使用 V1–V6。其余肢体导联由 I、II 推导：

```text
III = II - I
aVR = -(I + II) / 2
aVL = I - II / 2
aVF = II - I / 2
```

渲染顺序建议为 `I, II, III, aVR, aVL, aVF, V1–V6`。

### 3.3 增益限制

原始整数的量级接近微伏，常见量化阶跃约为 18–19，但当前没有采集器型号、标定脉冲或厂家格式说明，不能据此认定绝对单位。软件必须：

- 把 `µV/LSB` 作为可配置病例参数。
- 在未完成校准时显示“幅值未校准”。
- 不在未校准数据上自动给出 ST 幅度、QT 幅度或电压诊断。
- 保留 25 mm/s、10 mm/mV 等显示参数与真实数字标定的区别。

## 4. 窗口化读取和概览层

单例 `.DATA` 约 260–275 MB，不应一次性载入内存。推荐使用只读 memory-map 或按窗口定位读取。

读取 `[start_sample, start_sample + sample_count)`：

```text
seek(start_sample * 16)
read(sample_count * 16 bytes)
decode as little-endian int16[ sample_count, 8 ]
```

建议缓存层：

1. 原始层：200 Hz，只在当前 5–30 秒窗口读取。
2. 秒级概览层：每秒每通道保存 `min/max`，用于全程缩略图。
3. 趋势层：每 30 秒或 1 分钟保存有效心率的中位数、最小值、最大值和样本数。
4. 事件层：按 EBI 样本索引定位，不复制完整波形。

从 EBI 打开某搏动时，可读取 `sample_index - pre_samples` 到 `sample_index + post_samples`，例如前 0.6 秒、后 1.0 秒；边界必须截断到 `[0, frame_count)`。

## 5. `.EBI` 逐搏索引

### 5.1 结构

`.EBI` 为 32 字节文件头，之后为固定 24 字节记录。推荐暂按以下 little-endian 结构读取：

```text
<I H H I I I I
```

| 记录内偏移 | 类型 | 当前解释 |
|---:|---|---|
| `+0` | `uint32` | `.DATA` 采样索引 |
| `+4` | `uint16` | 保留；样本中为 0 |
| `+6` | `uint16` | 搏动分类码 |
| `+8` | `uint32` | 状态/模板 bitfield，未完全解码 |
| `+12` | `uint32` | 近似顺序号或 EBT 记录索引 |
| `+16` | `uint32` | 保留；样本中为 0 |
| `+20` | `uint32` | RR 间期，ms |

```text
record_count = (file_size - 32) / 24
```

若余数不为 0，必须拒绝按当前格式继续解析，并报告“未知或损坏的 EBI 版本”。

### 5.2 分类码

当前样本已验证的主分类：

- `1`：正常搏动 N。
- `2`：室上性搏动 S。
- `3`：室性搏动 V。
- `34`：伪差、排除或无效搏动。

统计总搏动时，现有报告通常为分类 `1 + 2 + 3`，不含 `34`。

### 5.3 RR 和有效性

瞬时心率：

```text
HR_bpm = 60000 / RR_ms
```

需要先排除：

- 首条 `RR=0` 记录。
- 分类 34。
- RR 超出当前设置范围；样本 XML 使用 300–3000 ms 作为 HRV 范围。
- 状态 bitfield 表示排除的记录。

`+8` bitfield 尚未完整反向解析。已观察到 `0x0000C100` 的较长 RR 被原报告排除。因此 MVP 应保留两套结果：

- “全部可读 RR”：仅做格式检查和数据审计。
- “报告有效 RR”：按已知分类、范围及状态规则过滤。

在 bitfield 规则完全验证前，不应宣称与原厂极值统计完全等价。

## 6. `.LPS` 报告解析

`*_1.LPS` 为带 BOM 的 UTF-16 XML，根节点为 `LrScriptPage`。报告文本主要位于：

```text
LrScriptPage/ShapeList/PShape[@SPTYPE='3']
```

常用字段可按文本前缀识别，例如记录时长、总心搏数、平均心率、最快心率、最慢心率、室上性心搏、室性心搏、最长 RR 和报告结论。`SPTYPE='4'` 常为 Base64 图片，不应当作普通文本载入界面。

安全要求：

- 默认不导入姓名、院内号、医生、科室等 PHI 到测试日志。
- 基线比较只保存病例目录 ID 和统计值。
- 解析失败时仍允许只读加载 DATA/EBI，不得因缺少 LPS 阻止波形查看。
- LPS 是历史报告结果，不等于当前 EBI 或当前算法结果；界面需显示来源和生成时间。

## 7. 心率趋势和直方图

### 7.1 心率趋势

- 逐搏值使用 `60000 / RR_ms`。
- 全程趋势建议按 30 秒或 1 分钟分箱，主值取中位数，另存最小/最大值。
- 分箱无有效搏动时显示缺口，不用 0 填充。
- 极值图条应定位到产生该极值的 EBI 样本索引，并展示前后上下文。

### 7.2 RR 直方图和 Lorenz 图

- RR 直方图只使用选定有效集合，横轴单位 ms。
- R/R 百分比可定义为 `RR_n / reference_RR × 100%`，但参考值必须在界面说明；若无法确认原厂定义，优先提供绝对 RR 直方图。
- Lorenz/Poincaré 图绘制 `(RR_n, RR_{n+1})`；只有连续有效 NN 对才进入 NN 图。

### 7.3 六类散点复核与圈选

- R-R、N、S、V 散点均以中间心搏 `beat_i` 为锚点，横轴为 `RR_i`，纵轴为 `RR_(i+1)`；N/S/V 按 `beat_i` 的源 EBI 分组筛选。
- N-N 散点要求 `beat_(i-1)`、`beat_i`、`beat_(i+1)` 连续三搏均为 N，且两个间期都在 300–2000 ms，避免跨 S、V 或噪声错误拼接。
- 小时散点取主波形焦点所在整点一小时（`hour_start_s = floor(focus_time / 3600) × 3600`），仅纳入该窗口内的有效心搏；横轴仍为 `RR_i`，纵轴为 `RR_(i+1)`。主波形跨小时后前端会刷新小时图并清空上一小时的圈选结果。
- R-R、N、N-N 和小时图为保证绘制流畅可确定性抽样；S/V 稀有点在不超过上限时全部绘制。接口同时返回完整候选数和实际绘制数。
- 鼠标圈线或键盘输入的矩形范围会转换为数据坐标多边形并提交服务端；服务端重新遍历完整候选集并将边界点计入结果，因此圈选片段不是仅从屏幕抽样点中选取。
- 圈内心搏样本索引按时间返回。界面只渲染滚动窗口附近的片段卡片，II、V1、V5 波形每批不超过 32 段、同时最多读取两批，并丢弃过期滚动窗口队列，避免大量片段造成内存或请求堆积。

## 8. HRV 算法

HRV 必须使用经过人工或规则确认的 NN 间期，不能直接使用全部 RR。

设 NN 序列为 `x[0..N-1]`，单位 ms：

- `SDNN`：全部 NN 的样本标准差。
- `SDANN`：各 5 分钟段平均 NN 的样本标准差。
- `SDNN index`：各有效 5 分钟段 NN 标准差的算术平均。
- `rMSSD = sqrt(mean((x[i] - x[i-1])²))`。
- `pNN50 = count(abs(x[i] - x[i-1]) > 50) / (N-1) × 100%`。
- 三角指数：有效 NN 总数除以固定宽度 NN 直方图的最高柱计数；直方图 bin 宽必须写入结果元数据。

频域建议流程：剔除异常 NN、形成时间戳、插值到等间隔序列、去趋势、加窗后使用 Welch PSD。样本 XML 的频段为：

- VLF：0.0033–0.04 Hz。
- LF：0.04–0.15 Hz。
- HF：0.15–0.40 Hz。

插值频率、窗口长度、重叠率和伪差修复策略会显著影响结果，必须版本化记录。未经与原厂逐例校验，不应宣称频域结果等价。

## 9. 基于现有标注的事件算法

以下算法用于整理已有 EBI 标注，不代表从原始波形完成新的医学诊断。

### 9.1 停搏、心动过缓和心动过速

- 停搏候选：有效 RR 大于等于配置阈值；样本 XML 为 2.5 秒。
- 心动过缓候选：有效逐搏 HR 低于阈值；样本 XML 为 50 bpm。
- 心动过速候选：有效逐搏 HR 高于阈值；样本 XML 为 120 bpm。
- 相邻候选只有在时间间隔小于配置容差时才合并为事件。
- 报告事件应保存起止样本、持续时间、最慢/最快 HR、有效搏动数和人工接受状态。

### 9.2 房性和室性事件

对分类 2 或 3 的连续模式可生成候选：

- 单发：相邻同类异常搏动未达到成对条件。
- 成对：两个相邻同类异常搏动。
- 短阵：至少 3 个连续同类异常搏动；具体终止间隔和心率阈值需配置。
- 二联律：重复 `N-X-N-X` 模式。
- 三联律：重复 `N-N-X` 模式。

所有事件必须允许人工接受、拒绝、改类和撤销。房颤不能由“分类 2 数量多”推断，应使用经验证的独立检测器或历史报告/人工标签。

### 9.3 ST、QT 和传导事件

当前数据缺少已验证的绝对增益、QRS 起止、J 点、T 波终点和导联质量标志。因此：

- 可以展示历史报告中的 ST/QT/传导事件和对应波形。
- 可以提供人工游标和测量工具。
- 不应在 MVP 中自动生成可用于临床结论的 ST、QT、束支阻滞或房室阻滞诊断。

## 10. 主要限制

1. 没有厂家公开格式说明，字段解释来自 10 例交叉验证。
2. `.DATA` 绝对电压增益尚未标定。
3. EBI `+8` 状态 bitfield 未完全解码，可能影响有效 RR、模板和极值。
4. `.EXAM/.DGS/.EVT/.EBT` 未完整解析。
5. 历史 LPS/PDF 可能与后来修改的 EBI 不属于同一分析版本。
6. 报告分类统计可能含人工修改、房颤区段排除或其他原厂规则，不能只按单一分类码求和。
7. 所有自动结果均需显示算法版本、参数、数据来源和人工审核状态。
