# 长 RR 图条：按真实 R 峰采样点校验入报边界

## 复现的问题

此前通过 `后一个 R 峰时间 - RR 毫秒数 / 1000` 反推前峰，用于入报游标边界判断。

- 200 Hz 下前峰样本 1（0.005 秒）、后峰样本 602（3.010 秒），精确 RR 为 3.005 秒。浮点减法得到前峰 `0.004999999999999893`，使合法起点 0.005 秒被误判为截掉前峰。
- 现有 RR 质量规则容许记录的 RR 与两峰样本差相差不超过 10 ms。该容差用于检查缓存一致性，不应被用于移动已知 R 峰位置。反推会错误接受少一个 R 峰的区间，或拒绝实际已含两个 R 峰的区间。

## 修复合同

1. 报告模块复用原有有效 RR 质量规则，投影前、后两个原始心搏引用；不排序、不跨越 X 拼接，不把 O/Y/T 当作 R 峰。公共 RR 质量算法源码保持原样，房颤冻结验证不受修改。
2. 长 RR 事件附带 `rr_start_sample` 和 `rr_end_sample`。事件的定位点仍为后峰，分类、数量和小时归属不变。
3. 图条解析重新从当前索引核实这一对端点，不能仅信任保存图条中的 RR 或传入坐标。无法唯一核实时拒绝并提示重新选择。
4. 人工起点先按既有采样网格归一化，再用整数采样点比较；起点等于前峰合法，越过一个样本即拒绝。区间右端仍为半开，必须在后峰之后。
5. 自动延长以真实前峰向前留 0.2 秒，并沿用至少 5 搏规则，不改变源波形。
6. 长 RR 选图依据从 `rr-gt2500-v3` 更新为 `rr-gt2500-v4-r-peaks`，旧选图保留但须重新选择确认，不静默升级。其他分类的专属版本规则不变。

Python 后端、浏览器算法及静态演示同步。仍严格使用 RR >2.5 秒及 >3 秒筛选规则；这是长 RR 候选，不等同已确诊停搏。未更改 RR 质量容差或估算电压设置。

## 验证范围

- 新增 32 项回归：精确采样边界、临近日末的位置、RR ±10 ms、越界一个采样点、半开右端、O/Y/T、X 端点、失配 RR、端点缺失、自动延长和旧依据拒绝。
- 隔离合成病例 API 链路验证：候选计数 → 合法／非法游标 → 保存 → 实际 PDF 构建；捕获 PDF 输入与预览比较，区间及全部导联样本一致。两个已知 R 峰均出现在原始 II 样本中。
- 非法选区保存被拒绝且不改变已保存版本；前峰改为 X 后计数归零、旧图条不能读取／导出。撤销后计数和精确选区恢复，但报告仍为草稿；源 DATA/EBI/LPS 字节摘要不变。
- 修复前新增用例 17 失败、11 通过，另 4 项在修复后加入。该失败集合包含新合同检查，不把全部失败都算作独立临床问题。
- 两轮综合专项分别 118 通过／1 失败、122 通过／1 失败。失败日志均是运行程序 `ctime_ns` 改变触发既有 409 保护，分别涉及 rr_quality / report_layout 与 rr_quality；未禁用该保护，具体元数据变更来源未确定。

- 首次完整回归 1,101 通过、1 失败、1 条既有 ZIP 警告（192.13 秒）。失败是新增接口改变了房颤开发验证冻结的 `rr-quality.js` 文件摘要；已将新接口移到报告模块，恢复公共 RR 文件原摘要 `7267f0849f34…`，没有更改冻结快照、验证阈值或测试门禁。

最终完整回归 **1,102 项通过，1 条既有重复 ZIP 测试警告（191.81 秒）**。修复后的专项 118 项通过，静态演示专项 5 项通过；JS 语法、镜像一致性及差异空白检查通过。本地服务健康检查正常，10 例可读、0 例不可读。没有使用患者病例执行保存、改型或撤销。

## 边界与下一步

这修正了已识别 R 峰的证据范围，不证明峰检测准确，也不把 200 Hz 导入假设变成设备验证。下一步持续跟踪运行时元数据变化来源，并在医生任务测试中核对长 RR 两端的原始波形和漏检／伪差。
