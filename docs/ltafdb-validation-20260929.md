# 冻结房颤候选的 LTAFDB 外部验证

## 结论与范围

已完成预定的 84 条公开记录、1,960.60 小时、两种心搏输入、三个模型的外部验证。熵候选整体减少误提示，但仍有个体漏提示退步、短事件丢失和严重输入质量问题，**不替换生产算法，不宣称自动房颤诊断或临床可用**。现有基线也未达到可靠自动诊断的证据要求。

数据：[PhysioNet Long Term AF Database 1.0.0](https://physionet.org/content/ltafdb/1.0.0/)，DOI 10.13026/C2QG6Q，ODC-By 1.0。引用 Petrutiu S, Sahakian AV, Swiryn S. Europace 9:466–470 (2007)；参考标注由 MEDICALgorithmics 人工复核。此次仅处理公开头文件和标注，未读取或上传本项目患者资料。

先写[固定协议](ltafdb-validation-protocol.md)，再检查输入词汇、边界和全部记录，之后才运行模型。全部 254 个输入文件验证官方摘要；未排除任何记录。自动 `.qrs` 的 N 不代表正常搏真值；配对 `.atr` 的人工复核心搏类型不能冒充本软件自动分类。自动文件中的人工 AF 终止 T 标记完全忽略，参考节律仅来自 `.atr`。

算法、质量门槛和熵阈值 **−1.35** 来自已冻结的 AFDB 开发结果。本库没有参与阈值选择；没有根据本库表现改变模型、增补平滑或筛掉困难病例。现在已经查看本库结果，今后不得把它再称为未见测试集。未据此证明跨数据库患者身份完全独立。

8,611,567 个自动心搏；其中未知参考时间 25.6783 小时单列，不作阴性。下表的 Se、Sp、PPV 均按时间计算；Se/Sp 只针对已评估时间，须同时看全参考 AF 捕获和未评估覆盖。

| --- | ---: | ---: | ---: |
| 全参考 AF 时间捕获 | 85.25% | 87.39% | 86.64% |
| 条件灵敏度 Se | 95.28% | 97.71% | 96.88% |
| 条件特异度 Sp | 77.65% | 93.06% | 93.57% |
| 候选时间 PPV | 83.41% | 94.32% | 94.67% |

熵候选额外未评估 AF 1,539.765625 秒、非 AF 410.234375 秒（65 个没有连续 12 个有效 RR 的窗口）。不能把这部分视作正确阴性。总体参考 AF 负荷为 53.28%，熵候选负荷为 49.36%；净负荷差不能替代逐段漏提示／误提示统计。

### 不利结果与失败定位

- 83 条有 AF 的记录中，熵候选有 9 条捕获下降超过 5 个百分点。05：100%→0%；47：99.00%→57.81%；32：88.79%→66.50%；37：83.16%→66.88%；100：59.41%→50.81%。所有逐记录结果保留，没有隐藏退步。
- 05 的三个参考 AF 段长分别为 13.2734375、5.015625、21.640625 秒，共 39.9296875 秒。与其相交的四个 30 秒窗都可评估，基线均提示；熵中位数分别约 −1.449、−2.138、−1.484、−2.001，均低于冻结阈值。这定位到短事件／混合窗口聚合失效，而不是质量弃权。参考中的短 AF 段只是数据集标注，不能直接解释为满足临床诊断时长标准。
- 103 在熵候选下仍有 11.323 h 非 AF 误提示，比基线 11.090 h 更差；22 仍误提示 4.909 h，PPV 仅 1.15%。不能从汇总 PPV 94.32% 推断每条记录可信。
- 112 的自动输入仅 8,861 个 QRS，参考输入为 116,161 个；自动 RR 中位数约 8,984 ms，全部 2,880 个窗口因有效间期不足而未评估。它是输入覆盖失败，不能表述成“未检出房颤”。122、208、62 的自动输入覆盖也很低。此次没有读取波形，不能据标注计数差异断言具体采集故障或 QRS 失败原因。
- 误提示时间主要落在参考 N（熵候选约 43.02 h），也包含 SBR、AB、SVTA 等节律；各分层均保存在结果中，不把这些混杂情形省略。

输入共 8,995,973 个参考心搏。心搏位置与类型同时变化，且 N-N 门控会排除非 N 间期，因此不能把与主输入的差异归因于某一个因素。

| 指标 | 现有基线 | 熵候选 | 熵＋转折率 |
| --- | ---: | ---: | ---: |
| 全参考 AF 时间捕获 | 79.43% | 81.98% | 81.18% |

## 输入适配与审计

- 128→200 Hz 整数时标映射，实测最大定位误差 2.5 ms；参考时间始终使用原始 128 Hz。质量阻断不会成为虚假 QRS，人工节律和 AF 终止信息不进入特征。
- 预检发现四类额外 NOTE（Aux/M/MB/PSE），不猜测医学含义，仅忽略并计数；记录 30 的一条 Aux 在录音终点之后，忽略而不扩展时长。细节和计数见固定协议及 `inventory.json`。这些格式修订发生在模型输出之前。
- 最初边界测试发现首条负采样索引 −1 未被拒绝，已修复；没有放宽真实 QRS／节律／MISSB 的边界检查。
- 新增适配／计时测试 30 项；与既有 AFDB／熵测试合计 66 项通过。完整软件回归 **988 passed，208.94 s**，1 条既有重复 ZIP 测试警告。不是临床性能认证。
- 504 个记录／输入／模型组合完成，3,528 项独立原始采样网格计时与区间求交比较，最大差 **0 秒**。470,544 条特征窗口、1,411,632 条模型输出均完整保存；未评估窗没有被输出成候选。
- 输入、活动源码及快照 SHA-256 全部复核一致。另对指定记录 00、30、105、208 的两种输入重新计算，8 组特征与保存的逐窗文件完全一致；这是结果后的复现抽查，不是全库第二次运行或预先规定的统计抽样。
- 本轮不改生产网页／算法、患者记录或报告，没有推送远端。

## 复现与交付

在 `requirements-validation.txt` 对应环境中，从仓库根目录运行（输出目录必须不存在）：

```sh
python scripts/validate_ltafdb.py --data /path/to/ltafdb-inputs --fetch --schema-only
python scripts/validate_ltafdb.py --data /path/to/ltafdb-inputs --preflight-only
python scripts/validate_ltafdb.py --data /path/to/ltafdb-inputs --output /path/to/new-results
```

已保存结果：`docs/validation/ltafdb-20260929/frozen-v1/`，含汇总、逐记录、输入清单、压缩逐窗特征／输出、开发参数和源码快照。运行后复核见同级 `postrun-verification.json`。环境 Python 3.12.14、NumPy 2.5.3、WFDB 4.3.1、Node v26.0.0。

下一步应在明确的开发协议中改善短事件／混合窗口聚合，并把输入覆盖不足与阴性结果严格区分；不能简单放松质量门槛或反复调本测试集阈值。需补充原始波形质量、QRS 输入验证，以及后续真正独立的数据、目标设备和医生完整任务验收。
