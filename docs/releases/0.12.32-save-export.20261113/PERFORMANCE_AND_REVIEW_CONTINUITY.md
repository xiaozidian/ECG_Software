# 保存、HRV 更新与 PDF 导出性能优化

本次发布减少重复分析、请求和序列化，同时保留医生已保存的复核、报告用途和审核状态。打开病例默认进入总览；总览、房颤编辑、ST-T 复核及报告编排共用界面资源。Windows 使用相同核心代码和界面，并保留原生启动与工作区适配。

- ST-T 保存使用与完整候选索引相同的心搏身份和资格规则，返回轻量回执，并减少重复请求。输入、标注或范围变化后，缓存会重新验证。
- HRV 更新复用相同输入的计算结果，继续检查完整版本与排除范围，保留撤销和回读。
- PDF 按实际选择的章节准备分析，减少未选章节的耗时；所选 ST/T 趋势和事件、HRV、房颤等仍获取相应完整数据。
- ST-T 与房颤保持独立；测量算法、NN 阈值、临床确认与入报选择不因缓存命中而改变。

## 保留原复核与审核

只有明确登记的已发布父程序、当前完整执行代码、原始数据内容、运行依赖和恢复标识全部匹配时，才尝试本次性能升级兼容。有效 ST-T 复核还逐条重算测量证据，并核对原保存心搏身份。兼容成功后，原标注、参考分析依据、表/文/图选择和报告签名保持原样，另外记录执行版本及验证证据。

原先已失效的复核不会恢复为有效。源数据、心搏、测量方法、代码或依赖存在实际变化时，不使用性能升级兼容；保留原有核对与导出保护。兼容策略和父程序清单均受启动后的文件变更检测保护。

## 验证范围

回归覆盖复核回执与完整候选索引等价、HRV 缓存及撤销、PDF 章节依赖、逐记录测量一致性、拒绝实际输入变化、原报告状态与签名保持、旧失效记录不恢复，以及跨平台共享源码和默认总览。公开 CI 使用数学构造数据；发布仓库和在线演示不携带真实病例或工作数据库。

在线演示运行浏览器数学数据适配；本地和 Windows 运行 Python 后端。三种入口的共享核心与界面通过源码指纹核对，原生启动器的必要适配单独验证。
