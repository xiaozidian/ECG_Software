# 修订后报告证据一致性验证 · 2026-09-29

## 结果与范围

修复心搏／节律修订后，前端旧事件、旧波形及人工文字确认状态可能残留的问题。报告草稿和医生正文保留；已失效选图必须重新筛选，人工文字需要重新核对。此轮不新增疾病诊断算法，不改变医学阈值，也不表示已完成临床有效性或机构部署验收。

## 复现与修正

| 问题 | 修正与证据 |
| --- | --- |
| 脏草稿刷新时，已删除的事件仍留在 `selectedLookup` | 刷新开始清空观察缓存，不清空人工选择。主列表与全部已选 ID 批次暂存，版本完全一致、全部成功后才发布。失败保留草稿并提供重试，不显示为无事件。 |
| 清空缩略图缓存后，旧请求仍可回填或占用同名待处理请求 | 引入代际隔离；清空时拒绝旧任务，晚到结果不能回填，也不能删除新一代同名请求。原有批处理、并发上限和 LRU 限制保留。 |
| 原始 DATA 内容改变但心搏 ID 不变，入报图可能复用旧缓存 | 缓存绑定病例、事件版本、源内容／后端算法摘要及复核修订号。跨代请求拒绝展示；缓存键携带依据，旧请求异常不能删除新缓存。 |
| 列表与后续图条读取跨越一次修改，可能混用不同依据 | `report-events`、`template-occurrences` 返回来源摘要及复核修订号；批量缩略图和入报图条接受预期依据，计算前后核对，变化返回 409。响应不包含源文件路径。 |
| 已确认人工文字在修改后仍显示已核对 | 本地存储和静态 Demo 在失效事务中保留文字，设置 `needs_review=true`、`acknowledged=false`；撤销也不恢复审核。节律标注变化清空相关分类筛选确认。 |
| 读取失败或人工文字待核对时，审核按钮仍可能可用 | 两处审核渲染共用门禁，明确显示读取中、失败或文字待核对。最终网页报告中直接显示人工文字及重新确认按钮，无需到另一子页寻找。后端审核校验继续保留。 |
| 移除失效选图后顶部计数残留 | 浏览器首轮复测发现并修复；移除动作同步更新报告壳层和内容，确认轮显示立即从 1 条变为 0 条。 |

新增回归最初运行 9 项全部失败，分别命中旧事件缓存、混合批次／读取失败、旧请求回填、四类人工确认失效及来源标识缺失。修复后扩大到 21 项，纳入完整套件。

## 自动验证

- 完整测试：**425 passed in 139.26s**，退出码 0。此前 404 项保留，新增 `tests/test_report_after_edits.py` 21 项；既有门禁及报告壳层测试补充新状态断言。
- 第一轮专项：79 项通过，24.44 秒；扩大后的报告／生命周期专项：50 项通过，20.95 秒。最终完整测试包含最后新增的失效选图计数回归。
- 合成 90 秒病例真实 API 链路：将一搏 N 改为 V → 完成测试复核并选择图条／保存／审核 → 改回 N，V 统计从 1 到 0、事件列表归零、旧报告转草稿 → 旧版本保存／导出被拒绝，失效图条不能导出 → 撤销后 V 统计恢复 1，但报告仍需复核 → 人工文字未重核时审核被拒绝，重核且保存后才允许测试审核。
- 上述链路前后 DATA、EBI、LPS SHA-256 相同。所有写入使用临时合成病例和临时数据库，不对正式患者作出诊断或审核。
- 注入原始信号替换、复核修订变化及计算过程中变化，四个读取接口按预期拒绝混合依据。浏览器逻辑测试执行实际源函数，覆盖来源变化但心搏 ID 不变、跨代晚到响应、混合批次、失败保留人工选择等。
- JavaScript 语法检查及 `git diff --check` 通过。静态 Demo 在新临时目录构建，定向同步 `index.html` 与 5 个本轮脚本；生成文件与源／构建文件逐字比对通过。没有提交、推送或部署到外部。
