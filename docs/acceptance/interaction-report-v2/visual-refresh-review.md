# visual-refresh 实测检查

2026-09-12。范围：同事新增的 visual-refresh.css、模板入口、静态 Demo 同步情况，以及实际运行的 http://127.0.0.1:8765。仅检查；未修改业务代码、样式、病例或报告。

## 结论

视觉体系与密度比上一版更统一，应保留这一方向。模板类型菜单和纵向滚动仍有效，HRV 长表收进面板的改动已生效；但最终报告可达性、有效提示文字对比及 Demo 同步尚未通过。不能将有限视口截图等同于完整功能验收。

## 按优先级排列的问题

1. **[P1] 最终报告内容被裁切，无法滚动查看。** 1366×768 下报告页底部是 y=768，内容底部约 y=1856；页面和报告内容滚动量均为 0。1920×1080 加载完成后同样存在，HRV 面板底部约 y=1758，超出报告容器。根因在 `static/css/app.css:105` 的固定视口高度和 overflow:hidden；`visual-refresh.css:96` 只调整该高度公式，没有建立新的内容滚动容器。这是上一版实现遗留的问题，并非同事新增；本次仍未解决。建议让 reportV2 获得可滚动的剩余高度，或使页面随内容增长；保留结论区时需避免覆盖正文。

2. **[P2] 新视觉层没有进入现有静态 Demo。** `templates/index.html:518` 已加载新 CSS，但 `docs/demo/index.html:503` 之后没有对应引用，`docs/demo/static/css/visual-refresh.css` 也不存在。开发页与当前交付 Demo 外观不同。现有构建脚本能够正确生成该资源，检查中仅向临时目录成功构建；没有覆盖交付目录。建议在确认修正后重建 docs/demo，并检查资源版本。

3. **[P2] 有效提示文字对比下降。** `static/css/visual-refresh.css:15` 将 --ink-300 从原覆盖值 #637986 改为 #a3b2ba。实际 ST-T 源报告空态提示使用 10px 该颜色，白底对比度约 2.18:1。这些是解释无数据原因的有效内容，并非禁用控件，浅灰使医生更难读清。建议将有效说明文字与禁用色分开，恢复可读的正文对比度。

4. **[P2] 窄屏流程条的行高与容器高度冲突。** `visual-refresh.css:79` 无条件设置两行 44px / 22px，覆盖已有窄屏三行布局；1280×768 实测生成第三行 26.5px，任务提示下沿 y=187.5，流程容器下沿 y=182。流程文字溢出容器约 5.5px，步骤行也被压到 22px。建议在对应媒体查询显式定义三行，或由内容决定高度。

## 实测通过

- 8765 开发页实际加载新视觉层；顶栏和流程条明显压缩，颜色、按钮与卡片更统一。
- 模板页保留 N / S / V 左下角菜单与参考图中的 S 模式；本次仅切换筛选，没有修改心搏和审核结果。
- 1366×768 模板页滚轮可下滑至底部；时间导航下沿 y=720，类型栏下沿 y=747，均可达。
- HRV 27 行长表限制为 200px 高的独立滚动表体，内容高度约 669px；指标卡顶部约 y=659，回到首屏。
- 没有记录浏览器控制台错误。静态构建脚本对新文件兼容，临时构建成功。设计检查器未报确定性问题；浏览器实测仍发现上述可达性问题。

## 对交付声明的校正

- “模板编辑画廊与波形同屏可操作”仅适用于足够高的窗口：1366×768 初次进入时底部时间条仍在视口之外，但现在能够下滑，属于可使用而非全量同屏。
- “ST-T 三栏一屏完整呈现”不适用于 1280×768：页面仍需纵向浏览，并发生自适应列布局。
- “关键 HRV 指标回到首屏”已验证；这不表示后续全天趋势图也全部在首屏。
