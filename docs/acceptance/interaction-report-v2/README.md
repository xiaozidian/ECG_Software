# 心电交互与报告流程优化：实施与验收

2026-09-12。本次实现依据用户最后确认的方案。总览与模板编辑独立，医生在模板编辑和 ST-T 完成诊断确认，在报告模块独立选择图条与文字。

## 交付

- `ecg_core/clinical_analysis.py` 与 `static/js/clinical-analysis.js`：Python / Demo 一致的全序列事件聚合、完整出现记录查询、版本依据和分窗 HRV。
- `static/js/clinical-ui.js`、`static/css/clinical-ui.css`：十二块横向波形浏览、按需加载、类型 / 模式 / 模板组合筛选、十二项报告导航、独立勾选、分类完成状态、图条排序和文字维护。
- `ecg_core/storage.py`、`ecg_core/review_workflow.py`：SQLite composition、结构化标注、报告版本冲突检查、诊断修改后失效；Demo 使用浏览器存储。
- `ecg_core/report_pdf.py`：选中波形的矢量 PDF、图注、诊断文字、全部已确认结果统计、分窗及逐小时 HRV。
- `docs/demo/`：由现有构建脚本生成的静态发布包，未手工修改生成文件。
- `report-selection-sample.pdf` / `.json`：公开十分钟 Demo 的三条实际波形图条、两种诊断文字；全量房早仍为 31 次 / 144 搏。样例标记为软件验收草稿，不代表临床审核。
- `scripts/build_report_selection_sample.py`：可重复生成样例。

## 数据接口

| 接口 | 用途 |
|---|---|
| `GET /api/cases/<id>/template-occurrences` | `class_code`、`mode`、`template_id`、`offset`、`limit`；稳定事件 ID、目标心搏、完整区间、总数和依据版本 |
| `GET /api/cases/<id>/report-events` | `category`、`mode`、`fast_slow_mode`、分页或 `ids` 查询；候选总数与已确认统计分开 |
| `GET /api/cases/<id>/hrv-windows` | `window` 从记录起点划分的 24 小时窗口；日间、夜间、小时表与实际覆盖时长 |
| `GET /api/cases/<id>/event-waveform` | `start`、`end`、`leads`、`max_points`；完整事件概览，读取量受输出点数约束 |
| `POST /api/cases/<id>/annotations` | 可附 `details.kind/status/end_sample/finding`；支持 ST、AT、VT、AF、AFL 结构化发现 |
| `PUT /api/cases/<id>/report` | `composition` 保存独立选择、顺序、图注、文字块、分类完成依据；`expected_version` 防止覆盖新版本 |

连续一、二、三、四搏以上分别聚合为单发、成对、三发、多发；重复节律至少两个完整周期。先识别完整序列，再按模板筛选。重复模式是重叠标签，不能累加为总事件次数。房速、室速不按连续数量自动诊断。旧 NPN 作为 NNP 的读取别名。房颤候选必须显式确认，不能自动作为已确认诊断入报。

波形概览使用原始设备数据和自适应幅度；较长事件可通过连续波形导航细看。此轮未增加 ST 自动定量诊断算法。形态叠加显示当前读取批次，完整出现记录的横向索引不受该批次限制。
