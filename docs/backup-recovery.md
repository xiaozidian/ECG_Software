# 本机已保存工作备份与恢复

## 备份范围和保管

设置页“已保存工作备份”保存 SQLite 内的标注、患者资料覆盖、模板、逐搏／节律修订与撤销记录、报告正文、选图、复核状态和审计。请先保存需要保留的修改，再勾选范围确认、点击“创建并校验本机备份”。成功后页面显示本机文件路径，列表最多展示最近 10 份，不自动删除旧备份。

**备份不包含原始 DATA／EBI／LPS、尚未提交的页面修改、配置文件和已导出的 PDF。** 必须另行保管原始数据与配置。同一磁盘的副本不是整盘故障的灾备。`.ecgbackup` 含患者健康信息且未加密，仅放在机构批准的受控目录；不要提交 Git、发送给未经授权的人或放入公开云盘。本功能不自动上传，也不提供 HTTP 下载或覆盖恢复入口。校验值只能发现意外改动，不是可信签名，不应恢复来源不明的包。

创建使用 SQLite Online Backup API，包含快照中已提交的 WAL 数据，不复制仍在变化的主库文件。发布前检查 ZIP CRC、SHA-256、SQLite 完整性、表结构及结构化字段类型；创建中途失败不会发布半包。正在运行的备份／校验不允许同一服务重复提交。默认数据库上限为 2 GiB；空间不足、读取失败或超时会报错，可修复条件后重试。备份期间仍可工作，但稍后提交的内容不一定在该快照内，应再做一份。原理见 [SQLite 官方备份说明](https://www.sqlite.org/backup.html) 和 [Python sqlite3.backup](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup)。

## 管理员命令

以下命令在软件源码目录执行，路径必须替换为自己实际的、经核对的路径。macOS 使用 `.venv/bin/python`；Windows 使用 `.venv\Scripts\python.exe`。已打包安装版尚未验证独立恢复入口，不能假定安装包自带 Python 或脚本。

```sh
.venv/bin/python scripts/manage_backups.py create --db "/实际工作库/cardioinsight.db" --destination "/受控备份目录"
.venv/bin/python scripts/manage_backups.py verify "/受控备份目录/work-实际名称.ecgbackup"
.venv/bin/python scripts/manage_backups.py restore "/受控备份目录/work-实际名称.ecgbackup" --new-app-data-root "/已存在父目录/尚不存在的恢复目录"
```

创建时不传 `--db` 将使用当前 `ECG_APP_DATA_ROOT`（未设置时为系统默认应用数据目录）内的 `data/cardioinsight.db`；不要凭默认值猜测正在使用的数据库。确认设置页位置及服务启动输出，优先显式指定。成功输出 JSON，失败退出码为 2。不要只看目标目录是否出现判断成功。

## 恢复顺序

1. 保留原工作区、原备份和原始心电数据。先停止旧服务、关闭旧页面，记录实际数据库／源数据／配置位置；不要删除或覆盖它们。
2. 先运行 `verify`，再运行 `restore`。目标必须尚不存在，父目录必须存在。已有目录、文件及链接均被拒绝；恢复不替换正在使用的库，不自动更改配置。若报告失败而新目录已出现，保留检查、另选一个新目录重试。
3. 成功后检查输出 `database` 路径及新目录的 `RECOVERY.json`。使用新应用数据目录启动，并显式指定原始 ECG 目录。macOS 示例：

   ```sh
   ECG_APP_DATA_ROOT="/已存在父目录/恢复目录" .venv/bin/python app.py --data-root "/原始心电数据目录" --no-browser
   ```

   Windows PowerShell 示例（环境变量仅作用于当前终端及其子进程）：

   ```powershell
   $env:ECG_APP_DATA_ROOT = 'D:\工作恢复\恢复目录'
   .venv\Scripts\python.exe app.py --data-root 'D:\原始心电数据' --no-browser
   ```

4. 按启动输出打开新地址，确认设置页显示“当前是恢复后的工作区”。检查病例、导联、时间、人工修订、模板、选图及正文；旧页面写入将被拒绝，需要重新打开。恢复产生新工作区标识，不能沿用旧的分析依据。
5. 恢复保留工作内容，但报告回到草稿，复核步骤失效、事件待复核，人工结论需要重新确认。重新完成模板／ST-T 复核、选图依据与人工文字确认后，再审核并导出。不要把“原报告已审核”当作恢复后仍有效。
6. 核对导出内容后才考虑后续切换；原库和原备份按机构保留策略保管。本工具不自动清理。返回原工作区需停止恢复服务，恢复原启动环境；恢复后新做的修改不会自动合并到旧库。

## 边界及验证

- 仅本机非演示、非代理服务可创建／校验；远程、只读演示及代理模式关闭入口。
- 文件权限尽量限制为本机用户；不替代 Windows ACL、磁盘加密、账号权限与机构隐私策略。
- 当前固定表结构校验只接受所支持版本；未来版本须提供迁移流程，不通过忽略不认识的表强行恢复。
- 使用本机支持硬链接与原子目录创建的文件系统；网络盘、FAT／exFAT、断电、目标 Windows 安装包及真实历史数据库迁移尚未专项验收。
- 自动测试使用一次性合成数据：已提交／未提交 WAL、损坏包、路径穿越、重复项、已有目标拒绝、磁盘空间、发布失败、超时、旧窗口拒绝、恢复后复核／选图／审核／PDF 链路及源文件哈希不变。浏览器状态测试涵盖范围确认、未保存报告、并发按钮、失败重试、列表刷新失败与恢复标识。
- 这是工作数据保全功能，不是临床有效性、不可篡改审计或完整灾备证明。工程验收结果见 [医生可用性矩阵](clinician-readiness.md)。
