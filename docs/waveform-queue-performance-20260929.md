# 小波形当前视野优先加载验证

日期：2026-09-29。范围是模板编辑出现记录的小波形请求调度，不更改心搏分类、临床算法、波形采样或报告测量。延续现有 Operate 模式与临床工作台布局。

## 问题与处理

此前队列虽已将同病例／导联请求合为每批最多 24 张、最多同时执行 2 批，但快速滚动或跳转后，已经离开缓冲视野的未发送请求仍留在 FIFO 队列。最新窗口会等待这些过期任务。

- 小波形请求新增消费方标识。出现记录每次渲染保留当前缓冲视野需求，取消仅属于该视图且尚未发出的过期任务，并将当前需求稳定排到前面。
- 默认消费方（包括报告）保持请求；同一 key 被多个视图使用时，释放一个视图不取消其他视图的需求。
- 已经发出的批次继续占用原并发槽并正常完成。浏览器取消请求不保证 Flask 停止计算，不能据此提前释放槽位并制造更多后端并发。
- 保留原有来源／修订代际校验、同 key 去重、192 项结果缓存、迟到结果隔离和失败重试。
- 离开编辑页才释放编辑需求；若导航被未保存修改保护拒绝，不释放仍在使用的窗口。隐藏页的迟到分页与尺寸更新不重新排入小波形任务。

实现：`static/js/waveform-loader.js`、`static/js/clinical-ui.js`；静态演示同步相同实现。

## 可复现调度验证

运行 `node tests/browser_waveform_queue.cjs benchmark`。实际加载器配合可控异步批次；没有浏览器、网络时间或患者数据。场景为已有 48 张分成两批执行，快速经过 20 个各 24 张的旧窗口，最终需要 24 张当前波形。

| 指标 | 原 FIFO 行为 | 当前视野保留策略 |
| --- | ---: | ---: |
| 总发送批次 | 23 | 3 |
| 当前窗口进入的批次序号 | 23 | 3 |
| 发出前取消的过期卡片 | 0 | 480 |
| 实际完成卡片 | 552 | 72 |

这里证明减少不再需要的排队工作，不表示整页响应提高约 8 倍。已经运行的两批仍完成；缓存命中、真实信号、磁盘与处理速度会影响用户等待。

## 后端只读测量

对临时合成的约十万心搏记录，Flask 测试客户端读取一批 24 个 2.4 秒、II/V1/V5 波形，三次约为 365、199、251 ms。合成 DATA 为稀疏零信号，不是临床录波或目标医生设备。带 cProfile 的一次约 407 ms，其中修订记录重建约 262 ms、24 次波形读取约 116 ms；计时含分析器开销，不与上面的直接计时相加。

此次没有修改后端读取或修订重建算法。后续优化必须继续保留删除／移位后的 RR 邻接关系和来源版本核对。

## 验证结果

- 完整回归：628 项通过，145.17 秒，退出码 0。唯一警告来自既有重复 ZIP 项拒绝测试。较此前 618 项新增 7 项队列与 3 项渲染／导航回归。
- 最终静态演示重建后，队列／渲染／波形性能／Demo 专项 60 项通过（6.54 秒）；生成的 `clinical-ui.js`、`waveform-loader.js` 与源码逐字一致，源码及演示 JavaScript 语法与 `git diff --check` 均通过。
- 队列测试覆盖旧窗口取消、报告共用需求、多个视图、取消后返回、在途请求、优先级和代际清理。渲染测试覆盖缓冲视野需求、空集合释放、非编辑页不排队、被拒绝导航不释放。
- 隔离浏览器使用独立数据库与纯合成 30 分钟病例；只在测试服务外层给批量波形接口增加 350 ms 延迟。连续跳转 100→400→700→1000→1300 后，最终窗口 24 张全部显示且无失败。
- 加载中更换参考导联为 I、跳转后进入报告，再返回编辑，波形恢复；卡片为 I/II/V1。第 600 条右击菜单仍为 D1 00:11:59.280，点击可定位连续波形。
- 390 px 检查跳转第 1000 条及 PageDown，显示范围前进至 1002–1005，缓冲内 6 张波形均显示。页面宽度与滚动宽度均 390，无横向溢出。浏览器未记录 warning/error。首次自动化使用 generic 角色定位器未命中，改用已在页面确认的列表 ID 后完成检查；不是产品失败。
- 测试服务与临时标签已关闭，视口设置恢复。没有刷新正式 8765 标签、重启正式服务、保存正式患者报告或进行推送。

## 剩余边界

本轮改善离开视野的排队请求，不解决已在执行的慢读取；不承诺所有目标电脑上的固定延迟。自动化与有限浏览器任务通过，也不替代医生实际设备、真实工作流或临床算法的专项验收。
