# 房颤筛查逐窗依据与波形复核

## 问题与实现

原有覆盖检查仅可回看“未评估”缺口；医生不能从该入口检查某个候选为何提示，或查看已评估但未提示的窗口。现在在“总览 → 房颤 / 房扑分析 → 检查全程覆盖 / 检查选区覆盖”下增加“逐窗提示依据”。

- 三种状态独立：不规则候选、已评估未提示、未评估；支持全部和状态筛选，每页最多 20 窗，保留绝对时间与原始窗口序号。
- 点击“查看依据与波形”同步 RR 选区和连续 ECG。波形附近展示有效 N-N / 窗口 QRS 条目、有效间期覆盖、连续间期对/三元组、CV、归一化 RMSSD、转折率，提供筛选内上一/下一窗口和返回同一页。
- 只消费 `screenAFResult` 原始浮点结果，不根据舍入值重新分类。未计算保留 null；未评估窗口的对/三元组内部初始值 0 也显示“未计算”。有效覆盖为 0 是可观测统计，与特征未计算不同。
- 明确工程规则不是诊断标准，未提示不能排除房颤、候选不是确诊。没有测量 P 波，不据此判定房扑。时间沿用当前导入采样率，不能替代设备确认。
- 结果绑定病例、逐搏修订、索引对象、载入代次与数据对象；重查清除旧证据。快速点击、切换筛选或新检查后，旧异步定位不再抢焦点；其他图形/片段定位清除原窗口依据。
- 不修改 `overview-engine.js` 或 `rr-quality.js`，不部署前一轮定位校正实验，不改变固定阈值、原始 DATA/EBI 或已保存诊断。覆盖明细仍为临时只读结果，不作为报告已保存证据。

## 交互取舍与验证

结合 redesign-existing-projects 的局部升级与 impeccable 的 harden 原则，保留临床工作台的白/灰/青色、紧凑布局和已有图形；明细默认折叠，不增加模态框或装饰图表。桌面六项指标按两行三列排列，窄屏两列，明确键盘焦点。

新增 31 项窗口快照、原始候选映射、null/数值边界、2,881 窗分页、状态筛选、真实 UI 函数与异步导航保护测试。包含实际 `seek` 与定位函数联合测试，避免仅依赖导航桩函数漏掉代次变化。专项加静态演示共 139 项通过（11.08 秒）。

真实浏览器使用独立合成数据与数据库，候选首窗显示 36/37、29.470 秒覆盖、CV 0.242、归一化 RMSSD 0.3591、转折率 0.6471；60–90 秒未评估，120–125 秒尾窗特征未计算。键盘及筛选路径完成后节律修订仍为 0，未保存任何诊断。桌面、窄屏可见性及无溢出确认，控制台无 error/warn。见 [截图来源与路径](validation/af-window-evidence-20260930/README.md)。

全量运行结果：1,452 passed、12 failed、1 warning，213.23 秒。失败涉及三例本地未下载完整输入及其引起的病例总数/默认样本变化，与此前失败集合一致；不修改数据保护或测试断言来掩盖失败。全量运行期间补充了导航代次收尾修复及两个回归，最终相关 139 项另行运行通过，未再次运行最终版本全量。

源脚本、样式与本地演示镜像同步；无远端发布。工程界面完成不表示整套临床产品完成。

## 未完成与下一步

已知固定 RR 筛查对定位误差和其他不规则心律敏感；本轮只增加可核查性，不提升灵敏度/特异度。需要继续固定协议的算法对照与医生实际工作任务验收，特别是全窗口核查、修订后重查、候选选图到报告的往返效率；真实设备标定仍缺失。
