# 总览、编辑与报告统计口径一致性

## 修正内容

- 总览／编辑摘要原先对平均心率隐含筛选 250–5000 ms RR，导致超过 5 秒的有效间期在报告存在、在摘要均值中消失。现在使用共享 RR 有效性检查，不以该范围隐藏间期；缓存 HR 还须与 RR 一致。
- 没有有效 RR 时最长间期显示缺失，不再用 `0` 代替。
- 总览长 RR 固定统计 `>2500 ms`，并列出其中 `>3000 ms` 的子集，与报告一致。编辑器可配置的 `≥阈值` 提醒独立保留，不混作报告固定阈值。
- 室早／房早百分比使用排除伪差后的有效心搏为分母；伪差比例使用全部 QRS／伪差标记为分母。非 QRS 标记和记录域外点不算心搏。
- 总览直方图和趋势绘制使用解码时得到的 RR 有效性标记，排除初始未测间期、与采样位置矛盾的 RR 及伪差两侧间期。统计在载入修订时计算一次，不随游标移动重复扫描全记录。
- 保留源报告估算作为独立对照；HRV 的连续正常 N-N 筛选依然独立，不能要求其样本量等于全部有效 RR。新增可展开的“查看统计口径”解释这些差别。

## 实现与测试

- `ecg_core/ebi.py` 与 `static/js/beat-engine.js`：统一摘要、计数及缺失值。
- `static/js/overview-engine.js`、`static/js/overview-workbench.js`：RR 有效性、固定阈值、分母及说明。
- `static/js/app.js`：无有效最长 RR 时保留 null。
- `tests/test_metric_denominators.py`：14 项新增测试，覆盖 2.5／3 秒严格边界、11 秒真实长间期、低于 250 ms 的有效间期、伪差、空记录、单搏、全伪差、记录末端、缓存 HR 冲突、前后端一致和真实 API 链路。测试没有重新定义正常 NN 条件。

全量回归 **869 passed，171.83 秒**，1 条既有重复 ZIP 拒绝测试警告；新增专项 14 项通过。静态演示构建在全新临时目录执行，只同步本轮四份脚本与带摘要的 HTML，未发布远端。

构建后专项加演示 **19 项通过**，四份源脚本与演示副本逐字一致，JS 语法及 diff 空白检查通过。正式 8765 服务按原命令重启后 `status=ok`，10 例可读、0 例不可读，工作台接口 HTTP 200；没有刷新用户原有页面。

## 浏览器验证

独立 8766 服务、独立数据库与纯数学信号；没有改写正式患者资料。90 秒合成记录含 82 条标记，其中 1 个 X、1 个 S、1 个 V，以及 8 秒长 RR。

## 边界与下一步

通过的是软件口径与合成输入一致性，不是设备采样率、自动诊断准确率或临床可用认证。来源 EBI 的原始检查仍保留其存储 RR，不悄悄修复原始字节；编辑分析使用物化后的当前修订。NN、分钟计数心率与有效 RR 平均心率含义不同，不强行合并。后续继续以逐搏参考标注及医生完整任务演练验证统计解释、纠错和入报行为。
