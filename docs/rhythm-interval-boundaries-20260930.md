# 房颤复核区间与正常间期统计的边界一致性

## 可复现问题

已保存标注的 `sample_index` / `details.end_sample` 都包含端点；房颤复核界面与分析使用半开时间区间。原共享转换漏掉末尾 `+1`，例如单采样标注 `[200, 200]` 被转换成空区间 `[1, 1)`，无法从正常间期统计排除。跨越末端采样点的 RR 也可能保留。当前导入约定为 200 Hz，因此这是一个采样点（5 ms）的口径错误，不代表确认了实际设备采样率。

报告事件索引还把房颤标注的包含末端直接当作 `end_s`，使 HRT / DC 从报告事件构造的排除区间存在同样的问题。

新增整采样网格参考测试另外发现：`ceil(10.005 * 200)` 的浮点误差可能多取一个采样点。规范化复核文档精度为毫秒，现先换算整数毫秒，再计算包含的末端采样点，避免为了规避浮点误差而随意加减时间容差。

## 变更与范围

- Python / JavaScript 的 AF、AFL 标注统一转换为 `[start_sample / 200, (end_sample + 1) / 200)`。待复核与已确认片段都排除出正常间期统计；已排除片段不排除。这沿用既有保守策略，不把待复核当成确诊。
- 房颤报告事件保留原包含末端 `end_sample`；`end_s` 改为对应半开终点，供持续时间、HRT / DC 等消费者一致使用。不会重写原标注、心搏或波形。
- 房颤事件依据增加 `inclusive-end-v1`，事件索引版本增加 `af-end-v1`，避免继续使用旧口径选图。正常心率候选已有排除区间摘要，会随实际区间变化失效；其他类型事件的专属依据不改。
- 正式服务与静态演示三份 JS 同步。没有修改自动房颤筛查的窗口、阈值、候选聚合规则，没有覆盖历史验证快照。

## 验证设计

`tests/test_rhythm_interval_boundaries.py` 使用独立的整数采样集合交集参考，而不只比较 Python / JavaScript 两份实现：

- 36 个 AF / AFL、pending / confirmed / excluded、首尾接触 / 单点 / 范围外组合。
- 随机重叠区间的采样集合并集参考。
- 单采样复核文档往返及 HRV 正常间期、连续差分数。
- 400 个靠近 10 秒和 24 小时的整网格／非整网格毫秒终点，跨实现核对取整。
- 报告 HRT 合格室早数、DC 锚点数随单采样标注减少，跨实现结果一致。
- 最快／最慢 NN 候选排除边界相交间期，RR 候选不受影响；旧房颤选图依据不能继续批准。
- 两个合成 HTTP 病例流程：保存待复核片段→排除→撤销→重做；简要 HRV、分窗 HRV、报告 HRV 三个端点同步。合成 5 ms 片段仅为工程边界夹具，不是临床 AF 事件。

首次运行新增测试为 14 failed / 26 passed，明确暴露漏端点及浮点多端点错误。修复后首批专项 94 项通过（16.03 秒），随后加入毫秒全网格和第二个 API 边界回归。既有测试中 0–200 包含末端的期望值从 1 秒修正为 1.005 秒，保留原 API、状态与计数断言。

首次完整回归为 2 failed / 1,296 passed（210.29 秒）：旧周期事件测试约定整个索引版本以 periodic-v2 结尾，现增加 AF 时间口径版本，更新为明确的新组合版本，但保留旧选图拒绝断言。另一项为 LTAFDB 历史评价的整文件冻结保护：当生产源码变化时应继续拒绝运行旧协议，不能把历史结论当作新构建验证。保留保护函数、全部摘要、源快照与阈值不动；改为分别测试原快照通过、当前生产构建因源码漂移被拒绝。没有重新执行或宣称本轮通过 LTAFDB 临床／外部性能验证。

## 边界与依据

[PhysioNet HRV Toolkit](https://archive.physionet.org/tutorials/hrv-toolkit/) 将正常窦性到正常窦性的 NN 序列作为传统 HRV 的基础，也指出早搏／伪差会影响结果。本轮只修复项目内部时间表示的契约，不声称该页面规定了本软件所有排除策略，亦不构成临床性能验证。

真实设备标定、独立算法评价及医生完整病例任务验收仍未完成。自动候选是否准确与存储边界是否正确是两件事。本轮不改 UI 布局，不以没有重新视觉验收来宣称界面优化；下一步核查毫秒边界在人工选图、节律负荷及跨小时统计中是否始终保持同一含义。
