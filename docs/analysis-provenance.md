# 报告计算依据与失效保护

更新：2026-09-30。这里记录工程上的版本一致性机制，不是电子签名、临床验证证书或防篡改存证。

## 绑定了什么

- 程序启动时记录后端分析／报告模块内容 SHA-256、应用版本、Python／NumPy／SciPy／ReportLab 版本及输入格式。显式模块清单在 `ecg_core/analysis_provenance.py`；以后增加影响计算的新模块时需更新清单。源码不可用的打包形态读取模块代码对象；PyInstaller 入口以可执行程序归档的内容指纹绑定。
- 每例的 DATA、EBI、LPS 记录文件字节数与内容 SHA-256，形成病例计算依据。对外的依据对象不包含绝对文件路径、姓名或原文。原始 PDF／PNG 仅为对照资料，不包含在本次计算依据中。
- 保存报告时同时保存当前计算依据及规范化报告配置的 SHA-256。配置包含导联、入报范围、页选择、研究测量参数、校准说明与人工 QT 端点；其他人工修订仍由病例复核版本保护。
- 主报告和独立 HRV PDF 在计算前后核对病例复核版本、报告版本和计算依据。成功响应返回 `X-Analysis-Basis` 与 `X-Report-SHA256`，后者是实际下载字节的 SHA-256；主报告另返回两个版本号。仅成功构建且通过一致性检查后记录成功导出审计。

## 变化后如何处理

1. 打开病例／请求病例 API 时核对当前依据。首次无历史复核的新病例只建立基线。
2. 已有依据变化，或旧数据库中的历史复核／报告没有来源记录时，原子地更新基线、撤销旧审核、使复核步骤和类别复核失效，推进版本号。已有事件接受／排除状态退回待复核。
3. 保留医生结论、已选图条、人工标注及编辑记录，避免删除劳动成果；**保留不表示这些内容仍然有效**。必须回看新依据并重新确认，失效的选图需重新选择。失效前的报告依据仍保留在旧草稿记录中，直到重新保存覆盖。
4. 新旧程序不能在运行中混用。启动后程序文件内容、mtime、inode、长度或设备变化，病例计算请求返回 409，提示完成更新并重启服务；源码注释等非数值变化也触发。仅 ctime 改变时，允许在读取前后及整组检查均稳定、长度和 SHA-256 与启动时完全相同的条件下更新元数据签名，构建与报告依据不变。校验失败仍拒绝；一旦检测到更新，即使随后恢复字节也必须重启。详见[元数据核验边界](runtime-metadata-20260930.md)。
5. 已审核报告缺少匹配的依据或配置摘要，不允许作为已审核报告导出。依据变化后的草稿仍按既有未审核规则导出；携带旧版本号的下载请求拒绝。
6. 只读服务不自行写入或重审历史报告；发现不匹配的历史依据，要求在可写工作站复核。没有历史记录的只读演示仍可运行。

失效、报告更新和审计在同一 SQLite 事务内，任何一步失败整体回滚。首次接入旧数据库会要求历史报告重新复核，这是迁移行为，不是结论丢失。

## 缓存与响应

内容哈希按文件设备号、inode、字节数、mtime 和 ctime 缓存（最多 64 项）；未变化的文件不反复读取全文。首次访问和文件变化后需要读取文件计算哈希，耗时受文件大小与磁盘影响。

校验包含单文件读取前后、缓存返回前后以及整个 DATA／EBI／LPS 文件集前后的一致性检查。EBI 记录／采样索引缓存、病例元数据缓存和 ST／高级测量缓存也使用包含 ctime／inode 的文件签名，防止同名、同长度、恢复 mtime 的替换仍沿用旧缓存。文件内容完全相同的重新写入不会单独撤销报告审核，但个别分析缓存会重新计算。

本机一次只读微基准：275,031,008 字节 DATA 的首次本进程摘要校验约 0.1396 秒，50 次缓存核对平均 0.575 毫秒。不包含整页绘制，不是清除系统磁盘缓存后的冷盘结果，也不代表其他设备的时延承诺。

### 云端占位文件

本轮完整回归实际遇到 macOS `compressed,dataless` 的约 261 MB DATA，栈采样显示进程停在系统 `read` 而非数值计算。新增 macOS `SF_DATALESS`（SDK `sys/stat.h` 定义为 `0x40000000`）读取前检查；波形、图条、密度、ST／高级测量、EBI 及摘要校验均不主动等待此类文件取回。病例 API 返回 `503 / source_not_local` 和下载到本地的操作提示。

暂时无法读取不会删除历史结论、选择或审核记录，但不允许据此导出；文件可读后重新核对内容，若实际内容变化才使历史审核失效。应将采集文件夹完整下载并保持本地可用。这里只识别 macOS 可观察的 dataless 标志，不声称覆盖所有网络盘阻塞或 Windows 云文件状态；系统可能在检查后才改变文件驻留状态。

### 结构损坏及读取失败

DATA／EBI／LPS 在病例读取时先做结构与采样范围校验，再建立计算依据。数据为空、半帧／半记录、心搏重复／乱序／越界、无效报告时间等返回 `422 / source_invalid`；缺失或读取权限失败返回 `503 / source_unreadable`。失败不改写已有报告或审计，原字节恢复后重新核对；源文件真实变化仍撤销旧审核。工作台展示不可读病例与重试入口，缺失计数保留未知。详细故障注入及恢复证据见 [专项记录](source-integrity-validation.md)。

## 验证与范围限制

运行期间模块变化另有隐私收敛的结构诊断日志和有界探测脚本；详见 [原运行程序变化诊断记录](runtime-guard-20260929.md)。2026-09-30 已补充“仅 ctime 变化且启动内容一致”的有界恢复；真实代码变化仍严格拒绝。已复现元数据变化引起旧策略拒绝的机制，不能据此确定此前的外部修改进程。

`tests/test_analysis_provenance.py` 的 33 项测试只修改临时合成输入，覆盖内容替换、恢复 mtime、缓存刷新、校验期间竞争、文件缺失、旧审核迁移、程序更新、事务回滚、只读保护、人工参数绑定、导出字节摘要、导出期间变化及失败不记成功；模拟 dataless 状态检查八个读取入口，以及 API 拒绝输出而不清除历史工作。打包入口有模拟代码路径测试，**尚未证明真实 macOS／Windows 安装包升级验收通过**。

不能据此声称完整来源重放或不可篡改：

- 数据库管理员和操作系统文件权限持有者仍可能篡改记录；没有签名密钥或防篡改审计链。
- 文件哈希缓存信任本地文件系统元数据变化；未设计对抗特权攻击或具有异常元数据语义的文件系统。
- 这不是文件系统原子快照或采集文件锁。末次检查以后发生的外部写入、先改再完全恢复的极短竞争，不提供完整排除保证。计算时应使用稳定、受控只读的已完成采集文件。
- 只保存摘要和当前记录，不保存旧算法安装包、原始数据历史副本或所有历史报告全文。摘要不能代替备份或重放。
- 后端计算构建被绑定，前端显示代码与目标打印机环境未纳入该清单。工作台列表显示最后保存状态；打开病例才触发此次内容核对。
- 正式服务需要重启才能加载修改；浏览器视觉交互验收、真实安装包迁移、独立算法对照及临床专家验证仍需另行完成。

与现有多窗口保护配合使用，见 [医生复核工作流](医生复核工作流.md) 和 [医生可用性验收矩阵](clinician-readiness.md)。
